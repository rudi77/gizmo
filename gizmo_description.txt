Unten ist eine **konkrete, realistische Anleitung**, wie du Gizmo als ersten lauffähigen Quadruped in Gazebo simulierst.

Ich nehme als Zielplattform:

**Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic / Gazebo Sim**

Das ist aktuell sinnvoller als Gazebo Classic: Gazebo Classic ist seit Januar 2025 End-of-Life, und ROS 2 Jazzy unterstützt Gazebo Classic nicht mehr offiziell. Für moderne ROS-2-Projekte wird Gazebo Sim mit `ros_gz` und `gz_ros2_control` verwendet. `gz_ros2_control` verbindet dabei die ROS-2-Control-Controller mit den simulierten Gazebo-Gelenken. ([Open Robotics Discourse][1])

---

# 1. Zielbild für Gizmo in der Simulation

Gizmo wird in der ersten Version so modelliert:

| Teil            | Beschreibung                                   |
| --------------- | ---------------------------------------------- |
| Körper          | ca. 10 cm lang, 6 cm breit, 4 cm hoch          |
| Kopf            | ca. 6 cm breit, 4 cm hoch, sitzt oben auf Hals |
| Gesicht/Display | schwarze Fläche vorne am Kopf                  |
| Beine           | 4 Beine                                        |
| Servos          | 2 pro Bein: Hüfte + Knie                       |
| Gesamt          | 8 Bein-Servos + optional 1 Kopfservo           |
| Arme            | kleine Deko-Arme, zunächst fix                 |
| Bewegung        | einfache Krabbelbewegung per Gelenkpositionen  |

Für Gazebo bedeutet das:

```text
base_link
├── head / display
├── left_front_upper_leg
│   └── left_front_lower_leg
├── right_front_upper_leg
│   └── right_front_lower_leg
├── left_rear_upper_leg
│   └── left_rear_lower_leg
└── right_rear_upper_leg
    └── right_rear_lower_leg
```

Die acht simulierten Servogelenke heißen:

```text
left_front_hip_joint
left_front_knee_joint
right_front_hip_joint
right_front_knee_joint
left_rear_hip_joint
left_rear_knee_joint
right_rear_hip_joint
right_rear_knee_joint
```

# 2. Installation

## 2.1 ROS 2 Jazzy installieren

Auf Ubuntu 24.04:

```bash
sudo apt update
sudo apt install software-properties-common curl gnupg lsb-release
sudo add-apt-repository universe
sudo apt update
sudo apt install ros-jazzy-desktop
```

Dann ROS 2 in der Shell aktivieren:

```bash
source /opt/ros/jazzy/setup.bash
```

Am besten dauerhaft in `.bashrc` eintragen:

```bash
echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

---

## 2.2 Gazebo-ROS-Integration und ros2_control installieren

Gazebo kann über ROS-2-Launch-Dateien gestartet werden; `ros_gz_sim` stellt dafür unter anderem `gz_sim.launch.py` bereit. ([gazebosim.org][2])

Installiere die wichtigen Pakete:

```bash
sudo apt update
sudo apt install \
  ros-jazzy-ros-gz \
  ros-jazzy-ros-gz-sim \
  ros-jazzy-ros-gz-bridge \
  ros-jazzy-robot-state-publisher \
  ros-jazzy-joint-state-publisher-gui \
  ros-jazzy-xacro \
  ros-jazzy-ros2-control \
  ros-jazzy-ros2-controllers \
  ros-jazzy-gz-ros2-control
```

Test:

```bash
gz sim shapes.sdf
```

Wenn Gazebo startet, passt die Basis.

# 6. Controller-Konfiguration

Erstelle:

```bash
nano ~/gizmo_ws/src/gizmo_description/config/gizmo_controllers.yaml
```

Inhalt:

```yaml
controller_manager:
  ros__parameters:
    update_rate: 100

    joint_state_broadcaster:
      type: joint_state_broadcaster/JointStateBroadcaster

    gizmo_joint_controller:
      type: joint_trajectory_controller/JointTrajectoryController

gizmo_joint_controller:
  ros__parameters:
    joints:
      - left_front_hip_joint
      - left_front_knee_joint
      - right_front_hip_joint
      - right_front_knee_joint
      - left_rear_hip_joint
      - left_rear_knee_joint
      - right_rear_hip_joint
      - right_rear_knee_joint
      - head_yaw_joint

    command_interfaces:
      - position

    state_interfaces:
      - position
      - velocity

    allow_partial_joints_goal: true
```

Der `JointTrajectoryController` ist praktisch, weil du später Bewegungsabläufe als Trajektorien senden kannst. Für echte Servos lässt sich dieses Prinzip später ebenfalls verwenden: Simulation und echte Hardware bekommen dann im Idealfall die gleiche ROS-Schnittstelle.

# 8. Launch-Datei für Gazebo

Erstelle:

```bash
nano ~/gizmo_ws/src/gizmo_description/launch/gazebo.launch.py
```

Inhalt:

```python
import os

from ament_index_python.packages import get_package_share_directory

from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription, TimerAction
from launch.launch_description_sources import PythonLaunchDescriptionSource

from launch_ros.actions import Node

import xacro


def generate_launch_description():
    pkg_gizmo = get_package_share_directory("gizmo_description")
    pkg_ros_gz_sim = get_package_share_directory("ros_gz_sim")

    xacro_file = os.path.join(pkg_gizmo, "urdf", "gizmo.urdf.xacro")
    world_file = os.path.join(pkg_gizmo, "worlds", "empty.world")

    robot_description_config = xacro.process_file(xacro_file)
    robot_description = robot_description_config.toxml()

    gazebo = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(pkg_ros_gz_sim, "launch", "gz_sim.launch.py")
        ),
        launch_arguments={
            "gz_args": f"-r {world_file}"
        }.items(),
    )

    robot_state_publisher = Node(
        package="robot_state_publisher",
        executable="robot_state_publisher",
        output="screen",
        parameters=[
            {"robot_description": robot_description},
            {"use_sim_time": True},
        ],
    )

    spawn_robot = Node(
        package="ros_gz_sim",
        executable="create",
        arguments=[
            "-name", "gizmo",
            "-topic", "robot_description",
            "-x", "0",
            "-y", "0",
            "-z", "0.12",
        ],
        output="screen",
    )

    load_joint_state_broadcaster = TimerAction(
        period=3.0,
        actions=[
            Node(
                package="controller_manager",
                executable="spawner",
                arguments=["joint_state_broadcaster"],
                output="screen",
            )
        ],
    )

    load_gizmo_controller = TimerAction(
        period=4.0,
        actions=[
            Node(
                package="controller_manager",
                executable="spawner",
                arguments=["gizmo_joint_controller"],
                output="screen",
            )
        ],
    )

    return LaunchDescription([
        gazebo,
        robot_state_publisher,
        spawn_robot,
        load_joint_state_broadcaster,
        load_gizmo_controller,
    ])
```

    'left_front_knee_joint',
    'right_front_hip_joint',
    'right_front_knee_joint',
    'left_rear_hip_joint',
    'left_rear_knee_joint',
    'right_rear_hip_joint',
    'right_rear_knee_joint',
    'head_yaw_joint'
  ],
  points: [
    {
      positions: [0.2, 0.5, -0.2, 0.5, -0.2, 0.5, 0.2, 0.5, 0.0],
      time_from_start: {sec: 1, nanosec: 0}
    }
  ]
}"

# 13. Einfacher Gait-Controller für Krabbeln

Jetzt bauen wir einen kleinen Python-Node, der Gizmo periodisch bewegt.

Erstelle im Paket `gizmo_control`:

```bash
mkdir -p ~/gizmo_ws/src/gizmo_control/gizmo_control
touch ~/gizmo_ws/src/gizmo_control/gizmo_control/__init__.py
nano ~/gizmo_ws/src/gizmo_control/gizmo_control/simple_gait.py
```

Inhalt:

```python
import math

import rclpy
from rclpy.node import Node

from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint


class SimpleGaitNode(Node):
    """
    Very simple gait generator for Gizmo.

    This is not yet a physically optimal walking algorithm.
    It is a first movement test:
    - diagonal legs move together
    - hip joints swing forward/backward
    - knee joints bend and stretch
    """

    def __init__(self):
        super().__init__("simple_gait_node")

        self.publisher = self.create_publisher(
            JointTrajectory,
            "/gizmo_joint_controller/joint_trajectory",
            10,
        )

        self.joint_names = [
            "left_front_hip_joint",
            "left_front_knee_joint",
            "right_front_hip_joint",
            "right_front_knee_joint",
            "left_rear_hip_joint",
            "left_rear_knee_joint",
            "right_rear_hip_joint",
            "right_rear_knee_joint",
            "head_yaw_joint",
        ]

        self.t = 0.0
        self.timer = self.create_timer(0.1, self.publish_gait)

    def publish_gait(self):
        self.t += 0.1

        # Gait parameters
        hip_amp = 0.35
        knee_base = 0.65
        knee_amp = 0.25
        head_amp = 0.25

        phase_a = math.sin(self.t * 2.0)
        phase_b = math.sin(self.t * 2.0 + math.pi)

        # Diagonal gait:
        # left_front + right_rear are group A
        # right_front + left_rear are group B
        left_front_hip = hip_amp * phase_a
        left_front_knee = knee_base + knee_amp * max(0.0, phase_a)

        right_rear_hip = hip_amp * phase_a
        right_rear_knee = knee_base + knee_amp * max(0.0, phase_a)

        right_front_hip = hip_amp * phase_b
        right_front_knee = knee_base + knee_amp * max(0.0, phase_b)

        left_rear_hip = hip_amp * phase_b
        left_rear_knee = knee_base + knee_amp * max(0.0, phase_b)

        head_yaw = head_amp * math.sin(self.t)

        positions = [
            left_front_hip,
            left_front_knee,
            right_front_hip,
            right_front_knee,
            left_rear_hip,
            left_rear_knee,
            right_rear_hip,
            right_rear_knee,
            head_yaw,
        ]

        msg = JointTrajectory()
        msg.joint_names = self.joint_names

        point = JointTrajectoryPoint()
        point.positions = positions
        point.time_from_start.sec = 0
        point.time_from_start.nanosec = 200_000_000

        msg.points.append(point)

        self.publisher.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    node = SimpleGaitNode()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()


if __name__ == "__main__":
    main()
```

# 15. Warum Gizmo am Anfang wahrscheinlich noch nicht perfekt läuft

Das Modell ist absichtlich einfach. Für eine gute Laufbewegung brauchst du später:

| Problem                    | Ursache                             | Verbesserung                              |
| -------------------------- | ----------------------------------- | ----------------------------------------- |
| Gizmo rutscht              | einfache Box-Beine, wenig Reibung   | Fuß-Links mit höherer Reibung             |
| Gizmo kippt                | Schwerpunkt zu hoch / Beine zu dünn | Körper tiefer setzen, Füße breiter machen |
| Beine zittern              | Controller zu aggressiv             | Damping, Massen und Gelenklimits anpassen |
| Bewegung wirkt unnatürlich | einfacher Sinus-Gait                | echte Quadruped-Gait-Logik                |
| keine echten Servowerte    | abstrakte Positionen in Radiant     | Mapping Radiant → Servo-PWM einführen     |

Für den ersten Meilenstein ist das aber gut: Du siehst, ob Gelenke, Achsen, Maße und Controller grundsätzlich funktionieren.

# 16. Nächster sinnvoller Ausbau: Füße ergänzen

Aktuell sind die Unterschenkel einfache Stäbe. Besser ist pro Bein ein kleiner Fuß:

```text
upper_leg
└── lower_leg
    └── foot
```

Der Fuß könnte ca. so sein:

```text
Länge: 2.5 cm
Breite: 1.5 cm
Höhe: 0.5 cm
```

Das verbessert die Stabilität stark.

# 17. Gesichtsausdrücke simulieren

Für die erste Version reicht:

```text
Display = schwarze Fläche
Augen = grüne Kugeln
```

Später gibt es drei sinnvolle Stufen:

## Stufe 1: Statische Gesichtselemente

Du modellierst:

```text
happy eyes
wink eye
smile mouth
```

als kleine Geometrien im URDF. Das ist einfach, aber nicht dynamisch.

## Stufe 2: Gesicht über ROS Topic

Du definierst ein Topic:

```text
/gizmo/face_expression
```

Beispiele:

```json
{"emotion": "happy"}
{"emotion": "wink"}
{"emotion": "sleepy"}
```

Ein eigener Node entscheidet dann, welche Visualisierung angezeigt wird.

## Stufe 3: Echtes Display später auf Hardware

Auf dem echten Roboter wäre das Display z. B.:

| Bauteil            | Funktion                              |
| ------------------ | ------------------------------------- |
| OLED / TFT Display | Gesicht anzeigen                      |
| Raspberry Pi       | LLM, Sprache, Logik                   |
| Mikrocontroller    | Servo-Steuerung                       |
| ROS 2 Node         | sendet Bewegungs- und Gesichtsbefehle |

In Gazebo kannst du das Display zunächst nur symbolisch simulieren.

# 18. Gizmo-Softwarearchitektur für später

Später sollte Gizmo so aufgebaut sein:

```text
Mikrofon
  ↓
Speech-to-Text
  ↓
Small LLM / Brain
  ↓
Action Router
  ↓
──────────────────────────────
↓              ↓             ↓
Movement       Face          Voice
Controller     Controller    TTS
↓              ↓             ↓
Servos         Display       Speaker
```

In ROS 2 könnte das so aussehen:

```text
/gizmo/user_text
/gizmo/brain/action
/gizmo/movement_command
/gizmo/face_expression
/gizmo/speech_output
```

Beispiel für eine LLM-Antwort:

```json
{
  "action": "move",
  "movement": "crawl_forward",
  "duration": 2.0,
  "emotion": "happy"
}
```

Der `Action Router` übersetzt das dann in:

```text
/gizmo_joint_controller/joint_trajectory
/gizmo/face_expression
```

# 20. Wichtigste Designentscheidung

Für Gizmo würde ich **nicht sofort versuchen, perfektes Laufen zu simulieren**.

Ich würde so vorgehen:

```text
1. Erst URDF sauber aufbauen.
2. Dann alle Servos einzeln bewegen.
3. Dann einfachen Gait.
4. Dann Füße/Stabilität verbessern.
5. Dann Gesichtsausdrücke.
6. Dann LLM-Brain.
7. Dann Hardware-Mapping.
```

Der entscheidende Vorteil: Wenn später echte Servos dazukommen, kannst du die gleiche Logik wiederverwenden. Gazebo ist dann dein virtuelles Testlabor, und der echte Gizmo bekommt später nur eine andere Hardware-Schicht unter derselben ROS-2-Control-Struktur.
