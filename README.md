# gizmo

A cute robot — currently a placeholder URDF + Gazebo Harmonic simulation
running on **Ubuntu 24.04 inside WSL2** with **ROS 2 Jazzy**.

## Stack

| Layer            | Version / Package                                  |
|------------------|----------------------------------------------------|
| OS               | Ubuntu 24.04 (noble) on WSL2 + WSLg                |
| ROS 2            | Jazzy Jalisco                                      |
| Simulator        | Gazebo Harmonic (via `ros-jazzy-ros-gz`)           |
| Control          | `ros2_control`, `ros2_controllers`                 |
| Sim <-> control  | `gz_ros2_control`                                  |
| Description      | `xacro`, `robot_state_publisher`                   |
| Trajectory       | `joint_trajectory_controller`                      |

## Layout

```
gizmo/
├── scripts/
│   ├── 01_install_gazebo_ros2_wsl2.sh   # one-shot apt install (uses sudo)
│   └── 02_test_gazebo.sh                # smoke test
└── src/
    ├── gizmo_description/               # URDF/xacro, ros2_control config
    │   ├── urdf/gizmo.urdf.xacro
    │   ├── config/gizmo_controllers.yaml
    │   ├── meshes/                      # drop STL/DAE here
    │   └── launch/
    └── gizmo_bringup/                   # launch files
        └── launch/gizmo_sim.launch.py
```

`build/`, `install/`, `log/` are generated by colcon and gitignored.

## First-time install

```bash
cd ~/repos/gizmo
chmod +x scripts/*.sh
./scripts/01_install_gazebo_ros2_wsl2.sh   # ~10-20 min, uses sudo
exec bash                                   # pick up ~/.bashrc
./scripts/02_test_gazebo.sh                 # sanity check
```

## Build & run

```bash
cd ~/repos/gizmo
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
ros2 launch gizmo_bringup gizmo_sim.launch.py
```

Gazebo Harmonic opens via WSLg with the gizmo placeholder spawned and
controllers `joint_state_broadcaster` + `paddle_position_controller` active.

## Quick commands

```bash
# Status
ros2 control list_controllers
ros2 topic info /clock

# Drive the paddle joint to 1.2 rad in 1 s
ros2 topic pub /paddle_position_controller/joint_trajectory \
  trajectory_msgs/msg/JointTrajectory \
  '{joint_names: ["paddle_joint"], points: [{positions: [1.2], time_from_start: {sec: 1}}]}' --once
```

## Notes / known traps (already worked around in this repo)

- **`<parameters>$(find pkg)/...`** in URDF does NOT work with modern Gazebo —
  it isn't expanded by gz sim. We resolve the YAML path at launch time and
  pass it via xacro mapping (`controllers_yaml:=...`).
- **xacro `Command` substitutions** must be wrapped in
  `ParameterValue(..., value_type=str)`; otherwise the launch system tries
  to YAML-parse the URDF string and fails with
  `Unable to parse the value of parameter robot_description as yaml`.
- **`/clock` bridge** (`ros_gz_bridge parameter_bridge`) is required when
  controllers run with `use_sim_time=true` — without it,
  `controller_manager` service callbacks stall and spawners time out.
- **Spawner timing**: chaining via `OnProcessExit` is racy because
  `ros_gz_sim create` exits before the controller_manager advertises its
  services. We use `TimerAction` with conservative delays instead, plus
  `--controller-manager-timeout 60`.
- **`set -euo pipefail`** in shell scripts: ROS setup scripts reference
  unbound vars, so the install/test scripts use `set -eo pipefail`.

## WSLg display sanity-check

If Gazebo can't find a display, from an elevated PowerShell:

```powershell
wsl --update
wsl --shutdown
```

Then start a fresh WSL shell and verify `$DISPLAY` and `$WAYLAND_DISPLAY` are set.
